# Выпуск версии

Публичный архив — `MacDraw-universal.zip`. Он содержит приложение для arm64 и x86_64, `INSTALL.txt` и `LICENSE.txt`. В релиз также загружаются отдельная инструкция и `SHA256SUMS.txt`.

## Подготовка

1. Измените `CFBundleShortVersionString` в `Resources/Info.plist`, например на `1.0.1`, и увеличьте целочисленный `CFBundleVersion`.
2. Добавьте описание в `docs/releases/v1.0.1.md`: изменения, требования, ограничения и результаты проверок. Не заявляйте нотариальное заверение, пока его нет.
3. Обновите README, `Resources/INSTALL.txt` и [VERIFICATION.md](VERIFICATION.md), если поведение изменилось.
4. Выполните `./scripts/test.sh` и `./scripts/package.sh`, затем ручные проверки из VERIFICATION.md.
5. Зафиксируйте изменения, отправьте их в `main` и дождитесь зелёного [GitHub Actions](https://github.com/vladilenm/mac-draw/actions).

## Публикация

Создание и отправка тега запускают публикацию для всех пользователей:

```sh
git tag -a v1.0.1 -m "Mac Draw 1.0.1"
git push origin v1.0.1
```

Workflow сначала выполняет проверки на Apple Silicon и Intel, затем собирает Universal-приложение. Публикация возможна только при совпадении тега с версией в Info.plist и наличии файла заметок. Права на запись выдаются только задаче публикации. Используется встроенный `GITHUB_TOKEN`, дополнительные секреты не нужны.

После завершения проверьте страницу релиза, три прикреплённых файла и ссылку скачивания из README. Скачайте опубликованный архив и проверьте его SHA-256. Не заменяйте файлы уже выпущенной версии молча: исправление должно получить новый номер.

Ручной запуск workflow и обычные push/PR проверяют код и создают артефакт сборки без публикации релиза.

## Подпись и первый запуск

Текущий скрипт использует **ad-hoc подпись**. Это позволяет проверить целостность приложения, но не удостоверяет личность разработчика и не является notarization. Для открытия скачанного приложения может понадобиться исключение в настройках безопасности macOS.

Чтобы в будущем убрать этот дополнительный шаг, нужна отдельная процедура [Developer ID](https://developer.apple.com/developer-id/) и [нотариального заверения Apple](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution): сертификат разработчика, hardened runtime, подпись с timestamp, отправка через `notarytool`, проверка результата и `stapler`. Сертификаты и пароли хранятся в секретах CI, а не в репозитории. Текущий workflow этого не выполняет.

## Если релиз оказался неудачным

Не перемещайте опубликованный тег и не удаляйте предыдущие рабочие релизы. Укажите проблему в описании неудачного релиза, верните статус Latest предыдущей рабочей версии через настройки GitHub Release и выпустите исправление с новым номером. Если рабочей предыдущей версии ещё нет, переведите неудачный релиз в draft до исправления и объясните недоступность загрузки в README.

Пользователь может завершить Mac Draw и заменить `.app` предыдущей версией из Releases. Автообновлений и формата сохранённых рисунков нет, миграция пользовательских документов не требуется.
